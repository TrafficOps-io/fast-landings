# trafficops.io — гайд по брендингу и визуальной айдентике

Версия: 1.2 · Дата: 14 сентября 2026 · Основа: текущее содержимое `packages/ui`, включая общий контейнер, шкалу маркетинговой типографики и шрифт Onest, поставляемые пакетом.

Документ предназначен для дизайнеров, разработчиков и подрядчиков, создающих айдентику компании, логотипы продуктов, сайты, презентации и другие брендовые материалы.

**Визуальная формула:** тёплая нейтральная основа, коралловый акцент, ясная типографика, тонкие линии и соединённые узлы. Композиция должна передавать порядок, связь между элементами и понятное управление сложными процессами.

## 1. Как читать и применять гайд

В документе разделены два уровня:

- **Основа из UI** — значения и решения, которые уже присутствуют в исходниках. Цвета, шрифт, устройство знака и размеры компонентов можно воспроизводить по этим данным.
- **Рекомендации для айдентики** — правила, предложенные в этом гайде для развития существующего языка: композиции логотипа, охранное поле, оформление носителей, иллюстрации и голос бренда. Они не означают, что такие макеты или мастер-файлы уже существуют.

Название `trafficops.io` используется как корпоративный бренд, а Fast Landings — как имя продукта. Локальные технические идентификаторы пакета не используются во внешних материалах.

Логотипы TrafficOps / PWApps / HookRoute и созданный в той же системе знак Fast Landings находятся в `resources/brand/`; актуальные формы и написание перечислены в разделе 6. Цвета интерфейса сохраняются; у логотипов собственный коралловый акцент.

При разработке продукта используйте общие токены и компоненты пакета. При подготовке внешнего носителя переносите их визуальные роли, сохраняя читаемость и характер бренда. Требования к читаемости из раздела 4 имеют приоритет перед буквальным повторением мелких размеров и прозрачностей текущего UI.

## 2. Характер бренда

**Интерпретация визуального языка UI и рекомендации для айдентики.**

| Качество | Как выражать в дизайне |
| --- | --- |
| Ясность | Один основной смысл в блоке, короткие заголовки, заметная иерархия |
| Управляемость | Упорядоченные модули, направленные связи, предсказуемое расположение действий |
| Точность | Ровные контуры, согласованные интервалы, минимум случайных деталей |
| Спокойствие | Большая доля нейтрального фона, свободное пространство, умеренная насыщенность |
| Человечность | Тёплые оттенки, мягкие углы, понятный текст без избыточного жаргона |
| Связность | Повторение мотива узлов и маршрутов в знаке, схемах и иллюстрациях |

Основная единица композиции — аккуратный модуль с понятной ролью. Коралловый выделяет точку внимания: знак, главное действие, активный маршрут или ключевую мысль.

## 3. Цветовая система

### 3.1. Основная палитра

**Основа из UI:** [theme.css](resources/css/theme.css). Названия оттенков в первом столбце введены для удобства дизайнеров; CSS-токены и HEX взяты из кода.

| Роль / условное название | Светлая тема | Тёмная тема | Токен |
| --- | --- | --- | --- |
| Акцент / коралл | `#E75D45` | `#FF8068` | `--color-primary` |
| Фон / тёплая бумага, тёмный графит | `#FBF7F2` | `#1D1A19` | `--color-base-200` |
| Поверхность / молочный, тёплый уголь | `#FFFDFB` | `#262220` | `--color-base-100` |
| Разделители / песочный, тёмный тауп | `#E7DDD6` | `#3B3430` | `--color-base-300` |
| Основной текст | `#241F1D` | `#F7F0EB` | `--color-base-content` |
| Вторичный текст / тауп | `#766E69` | `#B7AAA2` | `--color-secondary` |
| Контрастный нейтральный блок | `#2F2926` | `#F7F0EB` | `--color-neutral` |
| Текст на нейтральном блоке | `#FFFAF6` | `#241F1D` | `--color-neutral-content` |

В [app-chrome.css](resources/css/app-chrome.css) эти роли связаны с оболочкой продукта:

| Токен оболочки | Источник | Назначение |
| --- | --- | --- |
| `--ui-page` | `--color-base-200` | Фон страницы |
| `--ui-surface` | `--color-base-100` | Панели и поверхности |
| `--ui-border` | `--color-base-300` | Границы |
| `--ui-muted` | `--color-secondary` | Приглушённый текст |

`--color-accent` и `--color-accent-content` в текущей теме совпадают с коралловым. Несмотря на название, `accent-content` здесь не обозначает контрастный текст на коралловой заливке. Для текста на акценте в коде есть `--color-primary-content` и `--color-accent-foreground`; их применение требует учёта раздела 4.

### 3.2. Распределение цвета

**Рекомендации для айдентики.**

- За основу светлого носителя берите `#FBF7F2`, для карточек и внутренних областей — `#FFFDFB`.
- Для тёмного носителя используйте `#1D1A19` и `#262220`. Коралловый переключайте на `#FF8068`.
- Начальный ориентир для площади макета: 80% фоновых поверхностей, 15% нейтрального текста и графики, 5% коралловых акцентов. Это композиционный ориентир, а не правило подсчёта пикселей.
- Крупная коралловая плашка допустима как один фокусный элемент обложки. Для небольших надписей на ней используйте проверенную контрастную пару.
- Увеличивайте выразительность масштабом, отступами и композицией. Дополнительный яркий цвет вводите только с определённой ролью.

Чёрный `#000000` и белый `#FFFFFF` допустимы для монохромного воспроизведения и технических ограничений носителя. Основные брендовые фоны сохраняют тёплый оттенок.

### 3.3. Цвета состояний

**Основа из UI.** Эти цвета передают состояние системы; они не являются дополнительными акцентами для продуктовых логотипов.

| Состояние | Светлая тема | Тёмная тема | Токен |
| --- | --- | --- | --- |
| Успех | `#2F8A62` | `#58B887` | `--color-success` |
| Предупреждение | `#B66A1E` | `#E6A256` | `--color-warning` |
| Ошибка | `#C94F4F` | `#F07979` | `--color-error` |

В UI статусы оформлены через мягкую подложку и текстовую метку; цвет текста дополнительно смешивается с основным цветом текста. Поэтому HEX состояния сам по себе не описывает итоговый вид бейджа. См. [status-badge.blade.php](resources/views/components/status-badge.blade.php) и `.ui-status-badge` в [app-chrome.css](resources/css/app-chrome.css).

В новых материалах всегда подписывайте состояние. Коралловый акцент близок к красному ошибки, поэтому одной смены оттенка недостаточно для объяснения результата.

### 3.4. Служебные цвета

В теме есть шкала `zinc-50…950`, а в оболочке — цвета подсветки JSON. Они обслуживают интерфейс и код. Не превращайте их автоматически в палитру корпоративной айдентики или отдельные цвета продуктов.

Пары текста на заливках, явно заданные в теме:

| Токен | Светлая тема | Тёмная тема |
| --- | --- | --- |
| `--color-primary-content` | `#FFFFFF` | `#241F1D` |
| `--color-accent-foreground` | `#FFFFFF` | `#241F1D` |
| `--color-secondary-content` | `#FFFFFF` | `#1D1A19` |
| `--color-success-content` | `#FFFFFF` | `#14271D` |

`warning-content` и `error-content` явно не переопределены в общей теме. Для внешних макетов подбирайте текст по контрасту, не предполагая, что белый подходит к любой статусной заливке.

## 4. Контраст и читаемость

**Рекомендации для новых материалов и ограничения текущей палитры.** Для обычного текста используйте контраст не ниже 4,5:1. Для крупного текста допустимо 3:1; практический ориентир крупного текста — от 24 CSS px обычного начертания или от 18,67 CSS px жирного. Начертание 600 не следует автоматически считать достаточным основанием для пониженного порога. [W3C: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Необходимые для понимания элементы графики и визуальные признаки элементов управления должны иметь контраст не ниже 3:1 относительно соседних цветов. Тонкая декоративная граница панели может быть слабее, если она не нужна для распознавания элемента управления или смысла. [W3C: Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

Ниже приведён расчёт по относительной яркости sRGB для непрозрачных цветов. Значения округлены для показа; прозрачности, hover-состояния и наложение на изображения проверяются отдельно.

| Текст / графика | Фон | Контраст | Применение |
| --- | --- | --- | --- |
| `#241F1D` | `#FBF7F2` | 15,28:1 | Основной текст светлой темы |
| `#241F1D` | `#FFFDFB` | 16,06:1 | Основной текст на карточке |
| `#766E69` | `#FBF7F2` | 4,68:1 | Вторичный текст без снижения непрозрачности |
| `#F7F0EB` | `#1D1A19` | 15,34:1 | Основной текст тёмной темы |
| `#B7AAA2` | `#1D1A19` | 7,65:1 | Вторичный текст тёмной темы |
| `#FFFFFF` | `#E75D45` | 3,47:1 | Недостаточно для обычного мелкого текста |
| `#E75D45` | `#FBF7F2` | 3,25:1 | Крупный текст и различимая графика; не мелкие подписи |
| `#E75D45` | `#FFFDFB` | 3,42:1 | Крупный текст и различимая графика; не мелкие подписи |
| `#241F1D` | `#E75D45` | 4,69:1 | Рекомендуемая пара для мелкого текста на коралле |
| `#241F1D` | `#FF8068` | 6,63:1 | Текст на акцентной заливке тёмной темы |
| `#FF8068` | `#1D1A19` | 7,03:1 | Акцентный текст на тёмном фоне |

**Практическое следствие:** светлая тема сейчас задаёт белый `primary-content`. Эта пара не проходит порог 4,5:1 для обычных надписей. В новых брендовых макетах используйте `#241F1D` на `#E75D45`; перенос этого решения в UI требует отдельного изменения темы. Этот документ код темы не меняет.

Мелкие ссылки и надзаголовки на светлом фоне оформляйте основным цветом текста, сохраняя коралловый в линии, маркере или соседнем знаке. Ссылки внутри текста подчёркивайте. Текст с прозрачностью `/45`, `/58` или `/60` из существующих компонентов нельзя считать проверенным только потому, что он уже есть в UI.

Цвета `success`, `warning` и `error` светлой темы также не обеспечивают 4,5:1 при простом использовании как текст на `#FFFDFB`. Для небольших статусных надписей используйте контрастный основной текст и цветовой индикатор либо проверяйте итоговый стиль бейджа.

## 5. Типографика

### 5.1. Семейство и начертания

**Основа из UI:** основной шрифт — **Onest**. Стек из [theme.css](resources/css/theme.css):

```css
font-family: 'Onest Variable', ui-sans-serif, system-ui, sans-serif,
    'Apple Color Emoji', 'Segoe UI Emoji', 'Segoe UI Symbol', 'Noto Color Emoji';
```

Onest поставляется одним вариативным файлом с диапазоном начертаний 100–900; перечислять отдельные дискретные начертания больше не соответствует действительности. Сам UI-пакет объявляет стек, а загрузкой шрифта управляет приложение.

| Начертание | Использование |
| --- | --- |
| Regular / 400 | Основной текст и описания |
| Medium / 500 | Навигация, названия в списках, короткие подписи |
| Semibold / 600 | Названия продуктов, заголовки, ключевые значения |
| Bold / 700 | Словесная часть логотипов |

**Рекомендации для айдентики:** сохраняйте Onest в брендовых материалах, где он доступен. Для длинных текстов используйте 400, для смыслового акцента — 500–600. Для кода и технических идентификаторов допустим системный моноширинный шрифт; отдельная брендовая monospace-гарнитура в пакете не задана.

Для русской и украинской версий проверьте наличие нужных глифов в используемых файлах шрифта и фактическое отображение символов `Ё`, `Й`, `І`, `Ї`, `Є`, `Ґ`. Веб-стек допускает fallback, поэтому название шрифта в CSS не гарантирует одинаковый рисунок всех языков. В статичном макете задавайте совместимый шрифт явно и проверяйте переносы.

### 5.2. Масштаб интерфейса

**Основа из UI.** Пересчёт `rem` и стандартных классов Tailwind приведён для корневого размера 16 px.

| Элемент | Размер / интерлиньяж | Начертание | Источник |
| --- | --- | --- | --- |
| Название продукта в шапке | 14 / 17,5 px | 600 | `topbar`, `text-sm leading-tight` |
| Подпись `by trafficops.io` в шапке | 11 / 13,75 px | Наследуется | `topbar`, `text-[11px] leading-tight` |
| Заголовок страницы | 24 / 32 px | 600 | `page-header`, `text-2xl` |
| Заголовок сущности | 30 / 36 px | 600 | `record-shell`, `text-3xl` |
| Заголовок панели | 16 / 24 px | 600 | `panel`, `text-base` |
| Описание панели, метаданные | 14 / 20 px | Обычно 400 | `panel`, `list-row`, `text-sm` |
| Навигация раздела | 14 px; 12,8 px при ширине ≤480 px | 500 | `.ui-section-link` |
| Надзаголовок | 11,52 px | 600 | `.ui-eyebrow` |

Для заголовков страницы и сущности применяется `tracking-tight`, то есть `−0,025em` в текущей теме Tailwind. Надзаголовок использует верхний регистр и трекинг `0,11em`. Размер подписи в шапке — описание текущей реализации, а не универсальный минимум для носителей.

### 5.3. Масштаб внешних материалов

**Рекомендации для айдентики; в пакете эта шкала не задана.** Значения в px — отправная точка для веб-макетов при отображении 1:1, а не размеры для печати или презентационного проектора. Этот раздел про обложки, презентации, печать и другие внешние носители за пределами веба; масштаб маркетинговых веб-страниц пакета описан отдельно в разделе 5.4.

| Роль | Размер | Интерлиньяж | Начертание |
| --- | --- | --- | --- |
| Главный заголовок обложки | 48–64 px | 1,05–1,15 | 600 |
| Главный заголовок на мобильном | 32–40 px | 1,1–1,2 | 600 |
| Заголовок раздела | 28–36 px | 1,15–1,25 | 600 |
| Вводный абзац | 18–20 px | 1,45–1,6 | 400 |
| Основной текст | 16–18 px | 1,5–1,65 | 400 |
| Подпись | 12–14 px | 1,4–1,5 | 400–500 |

Сохраняйте короткие заголовки, естественный регистр и преимущественное выравнивание по левому краю. Для текстовой колонки ориентируйтесь на 55–75 знаков в строке. Верхний регистр используйте для коротких рубрик; длинные заголовки и абзацы набирайте обычным регистром.

### 5.4. Масштаб маркетинговых страниц

**Основа из UI.** Раздел 5.2 описывает масштаб интерфейса продуктов, раздел 5.3 — внешние материалы вроде обложек, презентаций и печати. Между ними оставался масштаб маркетинговых веб-страниц (лендинг и продуктовые маркетинговые контейнеры) — он не был описан ни там, ни там. Пакет задаёт его как шестиступенчатую шкалу токенов в блоке `@theme static`: `--text-display`, `--text-title`, `--text-heading`, `--text-lead`, `--text-body`, `--text-caption`, у каждого — модификаторы `--line-height` / `--letter-spacing` / `--font-weight`, где применимо.

Фактические вычисленные размеры шкалы (CSS px):

| Роль | Токен | 360 px | 1440 px |
| --- | --- | --- | --- |
| Главный заголовок | `--text-display` | 32 | 76 |
| Заголовок раздела | `--text-title` | 32 | 52,8 |
| Заголовок компонента | `--text-heading` | 25,6 | 33,12 |
| Вводный абзац | `--text-lead` | 16 | 16,56 |
| Основной текст | `--text-body` | 16 | 16 |
| Подпись | `--text-caption` | 14 | 14 |

Эту шкалу используют общая шапка, маркетинговые контейнеры во всех трёх приложениях и ритм разделов через `--ui-section-rhythm: clamp(4.5rem, 9vw, 8.5rem)`.

Словесная часть — Onest 700, 24 px, трекинг −0,055 em. Основные части наследуют цвет текста; акцент светлой темы `#F04426`, тёмной — `#FF7857`. Наложенные элементы используют `#FF7857` / `#FF9677`. Эти значения заданы в [brand.css](resources/css/brand.css) отдельно от цветов действий интерфейса.

### 6.3. Размеры и применение

Стандартный контейнер знака — 36 × 36 px; для горизонтальных HookRoute и Fast Landings — 44 × 36 px. SVG сохраняет пропорции через `viewBox`. На мобильных экранах в общей шапке остаётся знак, а ссылка сохраняет `aria-label`.

Полные логотипы используются в шапках, подвалах и формах входа; компактные знаки — в favicon. SVG-favicon каждого проекта содержит светлый и тёмный варианты через `prefers-color-scheme`. ICO служит запасным вариантом.

При масштабировании сохраняйте пропорции, направление стрелок, формы и число элементов. Не заменяйте знаки продуктов общим знаком. Прозрачные центры узлов и окна смартфона должны показывать фон носителя без видимых соединительных линий внутри.

## 7. Архитектура бренда и новые продукты

**Основа из приложений:** PWApps, HookRoute и Fast Landings используют общую шапку, отдельные продуктовые знаки и подпись `by trafficops.io`.

Продуктовая композиция строится так:

```text
[знак продукта]  Название продукта
                 by trafficops.io
```

Сохраняйте общими палитру, типографику, формы поверхностей и стиль связей. Отличайте продукты знаком, названием, смысловой иллюстрацией и содержанием.

Новые продуктовые знаки разрабатывайте как часть семейства с сопоставимым оптическим размером и коралловым акцентом.

В логотипах используйте написание `PWApps`, `HookRoute` и `Fast Landings`. Подпись `by trafficops.io` используйте последовательно. На корпоративном носителе достаточно знака и `TrafficOps`, без повторной подписи. Техническое имя проекта HookRoute — `hookroute`, Fast Landings — `fast-landings`.

В материалах с партнёрами разделяйте логотипы свободным пространством или тонкой нейтральной линией. Балансируйте их по оптическому размеру, сохраняя собственные цвета и пропорции каждого знака.

## 8. Геометрия, сетка и поверхности

### 8.1. Параметры существующего UI

**Основа из UI.** Размеры приведены для 16 px/rem.

| Элемент | Параметр |
| --- | --- |
| Поля и селекторы | Радиус `0.55rem` = 8,8 px |
| Панели и контейнеры | Радиус `0.75rem` = 12 px |
| Панель `.ui-panel` | Граница 1 px, внутренний отступ 20 px |
| Общая шапка | Высота 64 px; внутренние горизонтальные отступы 16 / 24 / 32 px по брейкпоинтам |
| Страница `page` | Вертикальный интервал 24 px |
| Контейнер `.ui-container` | Максимальная ширина 1280 px; горизонтальные отступы 16 / 24 / 32 px по брейкпоинтам, внутри max-width |
| Карточка сущности `record-shell` | Максимальная ширина по умолчанию 1152 px; основной вертикальный интервал 28 px |
| Строка списка | Вертикальные отступы по 14 px; промежуток между группами 12 px |
| Активный раздел | Коралловая линия толщиной 2 px |
| Обычный select | Высота 40 px |
| Компактный select | Высота 32 px |

Отступы `.ui-container` заданы внутри максимальной ширины — это условие, при котором общая шапка и содержимое `<main>` выстраиваются в одну и ту же коробку, а не деталь реализации.

У `.ui-panel` нет собственной тени: отделение достигается фоном и тонкой границей. Шапка использует 92% непрозрачности фонового цвета и `backdrop-filter: blur(14px)`; это локальный приём навигации, а не универсальное правило всех поверхностей.

### 8.2. Перенос в айдентику

**Рекомендации для айдентики.**

- Используйте базовый модуль 4 px для цифровых макетов и основную шкалу интервалов 8, 12, 16, 20, 24, 32, 48, 64 px. Существующие оптические исключения UI не нужно механически округлять.
- Выстраивайте общие оси: знак, заголовок, основной текст и ключевые блоки должны образовывать читаемую сетку.
- Для лендингов и широких носителей используйте 12 колонок, для мобильных — 4. Это рекомендуемая сетка новых макетов, а не сетка, объявленная в UI-пакете.
- Переносите радиусы пропорционально носителю. В обычном веб-интерфейсе сохраняйте токены; на плакате или слайде подбирайте масштаб визуально.
- Группируйте информацию отступами, заливкой и тонкими разделителями. Сохраняйте небольшое число уровней вложенности карточек.
- Тени оставляйте лёгкими и функциональными, например для всплывающего слоя. Для основных брендовых композиций достаточно плоских поверхностей.

## 9. Графика, паттерны, иконки и движение

**Рекомендации для айдентики на основе знака и геометрии UI.** Единой библиотеки продуктовых иконок, иллюстраций или motion-токенов в пакете нет.

### Связи и узлы

Используйте полые окружности, тонкие линии, развилки и модульные прямоугольники. Пусть схема показывает понятную последовательность: источник, обработку и направления. В одной иллюстрации достаточно выделить коралловым один основной путь; остальные связи могут быть нейтральными.

Паттерн может содержать произвольное число узлов. Он остаётся иллюстрацией и не подменяет брендовые SVG-знаки. В смысловых схемах подписывайте узлы и явно показывайте направление, когда оно необходимо.

### Фоновый паттерн

В [placeholder-pattern.blade.php](resources/views/components/placeholder-pattern.blade.php) есть диагональная штриховка с ячейкой 8 × 8 и толщиной линии 0,5 единицы SVG. Цвет линии этот компонент не задаёт.

Как развитие этого приёма допустим редкий низкоконтрастный паттерн в нейтральном цвете: на краю обложки, под схемой или в пустой области. Не размещайте плотную сетку или штриховку под основным текстом. Размер ячейки масштабируйте под носитель.

### Иконки и иллюстрации

Для новых пиктограмм используйте контурный стиль, сетку 24 × 24, штрих около 1,5–2 px и согласованные скругления. Сохраняйте одинаковую оптическую массу. Коралловый применяйте для активного состояния или отдельного смыслового акцента.

Для иллюстраций подходят схемы потоков, панели с данными, связи между модулями и аккуратные фрагменты продукта. Скриншоты показывайте с читаемым масштабом и короткой подписью; демонстрационные данные должны быть явно уместны для показа.

Если используется фотография, выбирайте спокойную композицию и тёплый либо нейтральный свет. Кислотные градиенты, глянцевый 3D, случайные неоновые эффекты и перегруженные технологические коллажи не входят в базовый язык этого гайда.

### Движение

Для переходов состояния стартовый диапазон — 150–250 мс с плавным замедлением. В брендовой анимации можно последовательно проявлять источник, две связи и конечные узлы. Движение должно помогать увидеть порядок действий; текст и управление должны оставаться доступны без анимации. Предусматривайте вариант с уменьшенным движением.

В существующем `text-link` задан переход 300 мс, но это отдельный стиль ссылки, а не общая motion-система.

## 10. Применение на носителях

**Рекомендации для айдентики; готовые шаблоны этих носителей в UI-пакете отсутствуют.**

| Носитель | Рекомендуемая композиция |
| --- | --- |
| Сайт компании | Корпоративный логотип, тёплый фон, крупный левый заголовок, один основной CTA, схема связей или продуктовый пример |
| Сайт продукта | Продуктовый логотип с подписью, конкретная задача пользователя, иллюстрация сценария, общая палитра и типографика |
| Приложение | Общая шапка, семантические токены, умеренные радиусы, читаемые статусы и заметное активное состояние |
| Презентация | Одна мысль на слайд, общий левый край, крупная типографика, 1–3 смысловых блока; коралл выделяет вывод или маршрут |
| Социальная обложка | Короткий заголовок, знак или продуктовый логотип, один графический мотив; читаемость проверена в миниатюре |
| Документ / коммерческое предложение | Светлая основа, тёмный основной текст, коралловые рубрики или тонкие линии, спокойные таблицы |

| Аватар / иконка | Крупный знак на сплошной фирменной подложке, проверенный в квадратной и круглой обрезке |
| Мерч / печать | Простой знак или горизонтальный логотип, достаточные поля, одноцветная версия при ограничении технологии |

Для презентаций проверяйте слайды в режиме показа; основной текст обычно требует 20–24 pt или больше в зависимости от дистанции. Для печатного документа отправная точка основного текста — 10–12 pt. Эти размеры подбираются для носителя отдельно и не выводятся из CSS.

Печатные цвета подбирайте по цветовому профилю и пробе на материале. HEX в этом гайде описывает sRGB; фиксированных CMYK- или Pantone-эквивалентов в исходниках нет. Не записывайте автоматическую конверсию как универсальный фирменный стандарт.

## 11. Голос бренда

**Рекомендации для айдентики.** UI-пакет не задаёт редакционную политику; следующие правила поддерживают его ясный визуальный язык.

Пишите спокойно, конкретно и по делу. Начинайте с задачи или результата пользователя. Используйте знакомые слова, активные глаголы и короткие смысловые блоки. Технические термины вводите там, где они помогают действовать.

| Контекст | Пример формулировки |
| --- | --- |
| Призыв к действию | «Создать кампанию», «Подключить источник», «Посмотреть пример» |
| Пустое состояние | «Пока нет подключений. Добавьте источник, чтобы получать события» |
| Успешное действие | «Изменения сохранены» |
| Ошибка | «Не удалось подключить домен. Проверьте DNS-записи и повторите попытку» |
| Продуктовый тезис | «Принимайте события и направляйте их в нужные инструменты» |

Это примеры тона, не утверждённые слоганы и не перечень гарантированных функций каждого продукта. Для внешних обещаний используйте подтверждённые возможности конкретного продукта. Избегайте превосходных степеней без основания, абстрактных обещаний и чрезмерных восклицаний.

- [ ] Логотип сохраняет геометрию, охранное поле и читаемость в итоговом размере.

- [ ] Статусы и важные связи понятны по тексту или форме, а не только по цвету.
- [ ] Светлая, тёмная и монохромная версии подготовлены там, где они нужны.
- [ ] Макет проверен в реальном масштабе, в миниатюре или на пробном отпечатке — в зависимости от носителя.
