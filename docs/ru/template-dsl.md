# Справочник DSL шаблонов, версия 1

DSL описывает редактируемые настройки, повторно используемые блоки разметки и страницы лендинга. При сборке значения настроек подставляются в HTML/PHP; структура формы получается из объявлений `@param`. Импорт, редакторы, состав ZIP и публикация описаны в [руководстве по шаблонизации](templates.md). Макросы запроса `{query.name}`, `{body.name}`, `{headers.name}` и `@validation` относятся к отдельному [request runtime](template-runtime.md).

Есть два представления шаблона:

- **Авторский DSL**: `@template`, `@param`, `@type`, `@block`, `@layout`, `@each`, `@if`, `@render` и `{{path}}` в текстовых исходниках.
- **Нормализованный JSON v1**: схема полей с типами `text`, `group`, `repeater` и HTML с выражениями `{{#path}}`, `{{/path}}`, `{{>partial}}`. Это внутренний формат движка; его синтаксис разметки отличается от авторского DSL.

Ни одно представление не выполняет PHP, Blade, JavaScript или произвольные выражения при разборе и подстановке настроек. PHP-код сохраняется для выполнения на сервере опубликованного лендинга.

## Полный минимальный пример

Сохраните этот исходник как `template.tpl`. Он самодостаточен и использует только встроенные типы и один объявленный тип объекта.

```html
@template "Отзывы" version=1 description="Заголовок и список отзывов"

@type Review
@param author String = "Анна" label="Автор" required
@param body Text = "Спасибо за полезный материал." label="Отзыв"
@param visible Boolean = true label="Показывать"
@endtype

@section content "Содержание"
@param title String = "Отзывы читателей" label="Заголовок" required
@param reviews Review[] label="Отзывы" min_items=1 max_items=10
@endsection

@block reviewCard(review: Review)
@if review.visible
<article>
  <h2>{{review.author}}</h2>
  <p style="white-space:pre-line">{{review.body}}</p>
</article>
@endif
@endblock

@layout
<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><title>{{title}}</title></head>
<body>
  <h1>{{title}}</h1>
  @each review in reviews:
    @render reviewCard(review)
  @endeach
</body>
</html>
@endlayout
```

Начальные значения — `title: "Отзывы читателей"` и один объект в `reviews`. Его значения берутся из полей `Review`. Имя секции `content` в пути не участвует: правильно `{{title}}`, а не `{{content.title}}`.

## Лексика, строки и комментарии

Директива начинается с `@` в начале физической строки; перед ней разрешены пробелы и табуляция. Объявление и его аргументы занимают одну строку. Закрывающая директива также занимает отдельную строку и не принимает аргументов. Так, `<div>@render card(item)</div>` — обычный текст, а не вызов блока.

Имена директив, опций, полей, типов, блоков и путей регистрозависимы: `@previewData`, `aiInstructions`, `String`, `title` и `Title` пишутся именно в выбранном регистре. Идентификаторы полей, секций, блоков и аргументов начинаются с латинской буквы и далее содержат латинские буквы, цифры или `_`. Для полей, секций и имен нормализованных фрагментов действует предел 64 символа. Имя авторского типа начинается с заглавной латинской буквы. Дефисы, кириллица, пробелы и начальный `_` в идентификаторах не поддерживаются; используйте их в `label`.

Аргумент без пробелов можно записать без кавычек, но строки удобнее всегда заключать в `'…'` или `"…"`. Обе формы обрабатывают обратную косую черту через PHP `stripcslashes`: `\n` превращается в перевод строки, `\t` — в табуляцию, `\\` — в одну обратную косую черту, `\"` — в кавычку. Одинарные кавычки не создают «сырую» строку. Реальный перевод строки внутри кавычек не допускается.

```text
@param title String = "Он сказал: \"Привет\"."
@param body Text default='Первая строка\nВторая строка'
@param enabled Boolean = false
@param size Number = 18 min = 10 max = 30 step = 2
```

`= значение` — сокращение для `default=значение`. Пробелы вокруг `=` необязательны. Значения `default` сначала читаются как строки; встроенные типы `Number`/`Range` преобразуют числовые строки в числа, `Boolean` преобразует `true`/`false` в логические значения. Для `String` строка `"false"` остается строкой. Числовые опции `min`, `max`, `step`, `min_items`, `max_items`, `version` преобразуются отдельно.

У DSL нет собственного синтаксиса комментариев: `//`, `#`, `@comment`, `{{-- … --}}` и `{{! …}}` не являются комментариями DSL. Не добавляйте комментарий в конец объявления. HTML-комментарий внутри `@layout` или `@block` сохраняется в результате, а содержащиеся в нем выражения `{{…}}` продолжают обрабатываться. Многострочный HTML-комментарий не выключает распознавание директив на отдельных строках. Вне тела разметки допустимы пустые строки, но не HTML-комментарии.

Чтобы вывести строку, начинающуюся с `@`, используйте `@@`:

```html
@layout
@@example — эта строка начнется с одного знака @.
<p>Буквальная запись выражения: &#123;&#123;title&#125;&#125;</p>
@endlayout
```

`@@` не экранирует `{{…}}`. Для буквальных фигурных скобок в HTML используйте сущности, как в примере. Строки с CSS-директивами `@media`, `@supports`, `@font-face`, `@keyframes`, `@import`, `@layer`, `@container`, `@charset`, `@page`, `@property`, `@starting-style`, `@namespace`, `@scope`, `@counter-style` разрешены в разметке без удвоения `@`. Другую директиву CSS, начинающую строку, можно записать через `@@`.

Исходники должны быть UTF-8 без нулевых байтов. CRLF и CR нормализуются в LF. PHP-фрагменты непрозрачны для DSL: находящиеся в них `{{…}}`, строки с `@` и макросы запроса сохраняются как PHP-код. Границы `@layout`/`@endlayout` распознаются отдельно, в том числе после незакрытого конечного PHP-блока.

## Объявления

### `@template`

```text
@template "Название" version=1 description="Описание"
```

Допустимые опции: `version`, `description`, `previewData`, `previewUrl`. Объявление необязательно: по умолчанию используются версия `1` и имя `Imported template`. Во всем шаблоне, включая подключенные исходники и дополнительные страницы, допускается только одно `@template`.

`version` должен быть целым числом `1`. Имя — непустая строка до 200 байтов; описание — до 2000 байтов и может быть пустым. Неизвестные опции отклоняются.

### `@section` и `@param`

```text
@section appearance "Оформление"
@param accent Color = "#0f766e" label="Основной цвет"
@param fontSize Range = 18 label="Размер текста" min=14 max=24 step=1
@endsection
```

`@section id "Название"` группирует поля в форме. Название необязательно и по умолчанию совпадает с `id`. Секции не вложены, их идентификаторы уникальны. `@param` вне явной секции попадает в автоматически созданную секцию `general` с названием `General`; если нужна собственная секция `general`, объявите ее до таких параметров.

Общий синтаксис поля:

```text
@param name Type [= "default"] [option=value ...]
```

Корневые имена полей уникальны во всех секциях. Внутри объекта имена уникальны в пределах этого объекта. Например, `author.name` и `editor.name` могут сосуществовать, а два корневых `title` в разных секциях — нет.

| Опция | Назначение |
| --- | --- |
| `label="…"` | Подпись поля, до 200 байтов. По умолчанию имя поля; для одиночного объекта — пустая строка. |
| `help="…"` | Подсказка в форме, до 2000 байтов; пустая строка допустима. |
| `aiInstructions="…"` | Инструкции генератору содержимого, до 10 000 байтов; пустая строка допустима. |
| `required`, `required=true`, `required=false` | Обязательность значения. По умолчанию `false`. |
| `default=…`, `= …` | Начальное значение. |
| `options="value:Label\|other:Other"` | Варианты `Select`; подробнее ниже. |
| `min`, `max`, `step` | Числовые ограничения `Number` и `Range`. |
| `min_items`, `max_items` | Число элементов массива авторского типа. |
| `aspect_ratio`, `sizes` | Ограничения изображения; только `Image`, одновременно использовать нельзя. |

Указывайте каждую опцию один раз. Опции с `key=value`, повторяющие ранее заданное значение, отклоняются. Используйте опции только с типами, для которых они имеют смысл: например, `min` у `String` не задает минимальную длину, а `max_items` не ограничивает число символов.

### Встроенные типы и значения

| DSL | Тип в JSON | Допустимое значение и начальное значение без `default` |
| --- | --- | --- |
| `String` | `text` | Строка до 10 000 байтов; `""`. |
| `Text` | `textarea` | Многострочный текст до 100 000 байтов; `""`. |
| `Wysiwyg` | `wysiwyg` | HTML до 100 000 байтов, сохраняемый после очистки; `""`. |
| `Markdown` | `markdown` | Исходник Markdown до 100 000 байтов; `""`. |
| `Color` | `color` | `#RGB`, `#RRGGBB` или `#RRGGBBAA`; `"#000000"`. |
| `Number` | `number` | Конечное число с учетом `min`/`max`/`step`; `min`, если задан, иначе `min(0, max)` при заданном `max`, иначе `0`. |
| `Range` | `range` | Те же правила числа; отображается ползунок. |
| `Boolean` | `checkbox` | Логическое значение; `false`. |
| `Select` | `select` | Ключ из `options`; первый ключ. |
| `Image` | `image` | HTTP(S) URL или безопасный относительный путь; `""`. |
| `Url` | `url` | Абсолютный HTTP(S) URL; `""`. |
| `Email` | `email` | Email-адрес; `""`. |

`Integer` не является встроенным типом настройки DSL. Он существует в правилах request runtime; для целочисленного поля формы используйте `Number step=1` и подходящую базу `min`.

Текст должен быть UTF-8. Нулевой байт и управляющие символы запрещены, кроме табуляции и переводов строки. Все пределы строк указаны в байтах, поэтому кириллица занимает больше одного байта на символ.

Числовые `min`, `max`, `step` должны быть конечными числами; `min <= max`, `step > 0`. Шаг проверяется относительно `min`, если он задан, иначе относительно нуля: `(value - base) / step` должно быть целым с допуском `0.000001`. `Number min=1 step=2` принимает `1`, `3`, `5`. Необязательное числовое поле может содержать `""`.

При передаче значений движку `Boolean` принимает `true`, `false`, `0`, `1`, `"0"`, `"1"`. Строки `"true"` и `"false"` в данных не принимаются; преобразование этих слов действует для объявленного в DSL `default`. При обычном выводе логическое `true` превращается в `1`, `false` — в пустую строку.

`required` проверяется при валидации значений для генерации и preview. Пустые или состоящие из пробелов строки отклоняются. Для `Wysiwyg`/`Markdown` проверяется содержимое после очистки; `<p><br></p>` пуст, изображение или горизонтальная линия считаются содержимым. `required` у `Boolean` не требует галочки: `false` допустим. У объекта обязательность задают его дочерние поля; у массива `required` дополнительно требует хотя бы один элемент.

Значение по умолчанию проверяется по типу и ограничениям при импорте. При этом обязательные текстовые поля могут иметь пустой default, чтобы пользователь заполнил их позже. Отсутствующие ключи данных дополняются defaults; неизвестные ключи отклоняются, включая вложенные объекты. Явный `null` для обычного скалярного поля преобразуется в `""`, но не заменяется default. Для объектов, массивов и `Boolean` `null` недопустим.

### `Select`

```text
@param alignment Select = "center" label="Выравнивание" options="left:Слева|center:По центру|right:Справа"
```

Разделитель вариантов — `|`, первое `:` отделяет значение от подписи. Без `:` подпись совпадает со значением. Значения уникальны; допустимо от 1 до 100 вариантов. Ключ — до 200 байтов и может быть пустым; подпись — непустая строка до 200 байтов. Символ `|` внутри значения или подписи DSL не экранируется отдельным механизмом. Пробелы вокруг частей не удаляются автоматически, поэтому не добавляйте их вокруг разделителей.

Числовые значения данных преобразуются в строки, затем проверяются по ключам вариантов. Пустое значение допустимо только при наличии пустого ключа в `options` и отсутствии `required`.

### Изображения и URL

```text
@param logo Image = "assets/logo.png" label="Логотип"
@param cover Image label="Обложка" aspect_ratio="16:9"
@param avatar Image label="Аватар" sizes="256x256|512x512"
@param link Url = "https://example.com/article" label="Ссылка"
```

URL не может содержать учетные данные, пробелы, управляющие символы или обратные косые черты. Для `Image` допустим путь вида `assets/images/photo.webp`; недопустимы `/photo.webp`, `//host/photo.webp`, `../photo.webp`, сегменты `.`/`..`, пустые сегменты, query/fragment в относительном пути, схемы `data:`, `file:` и `javascript:`. URL или путь ограничен 2048 байтами. Кодированные обходы пути и управляющие символы также отклоняются.

В DSL `aspect_ratio` задается строкой `ширина:высота`, например `"16:9"` или `"3:2"`, с целыми положительными частями до пяти цифр. Полученное отношение должно лежать в диапазоне от `0.01` до `100`. Текущий DSL не преобразует десятичную строку `aspect_ratio=1.5` в число: для такого отношения используйте `"3:2"`. Нормализованный JSON, напротив, принимает число `1.5`.

`sizes="1200x630|1080x1080"` задает от 1 до 10 различных размеров. Ширина и высота — целые от 1 до 4096 пикселей, разделитель — строчная латинская `x`. В JSON это массив объектов `{"width":1200,"height":630,"label":"Обложка"}`; необязательная подпись — до 100 байтов без управляющих символов. После нормализации `aspect_ratio` становится числом, а отсутствующая подпись размера — пустой строкой.

Эти опции задают требования к загружаемым изображениям и параметры редактора кадрирования. Они не скачивают и не изменяют внешний URL или уже имеющийся путь. Работа с загрузками и редактором описана в [руководстве](templates.md).

### Форматированный текст

```html
@param article Wysiwyg = "<p>Короткая <strong>статья</strong>.</p>"
@param details Markdown = "## Подробности\n\nТекст с **выделением**."
@layout
<article>{{& article}}</article>
<section>{{& details}}</section>
@endlayout
```

`{{path}}` экранирует сохраненную строку; для отображения форматирования используйте `{{& path}}`. Оператор `&` разрешен только полям `Wysiwyg`/`Markdown` и зарегистрированным типам, отображаемым в эти контролы. Он работает во вложенных объектах, блоках, циклах и JSON partials.

Markdown преобразуется через CommonMark, затем HTML обоих форматов проходит очистку. Разрешены абзацы, переносы, заголовки, выделение, списки, цитаты, код, ссылки, изображения и горизонтальные линии. Скрипты, обработчики событий, inline-стили, iframe и SVG-разметка удаляются; сырой HTML в Markdown удаляется. `Wysiwyg` хранит очищенный HTML, `Markdown` — редактируемый исходник.

Размещайте форматированный вывод в HTML-контейнере (`article`, `section`, `div`), которому можно содержать блочные элементы. Не помещайте его внутрь атрибута, `script`, `style` или окружающего `p`: движок проверяет тип поля, но не исправляет неподходящий HTML-контекст. Типографику и стили изображений задает сам шаблон.

## Авторские типы и массивы

```text
@type Author
@param name String = "Редакция" label="Имя"
@param photo Image label="Фото"
@endtype

@type Article
@param title String = "Новая статья" label="Заголовок"
@param author Author
@endtype

@param article Article label="Статья"
@param related Article[] label="Еще статьи" min_items=0 max_items=5
```

В теле `@type Name … @endtype` разрешены только `@param` и пустые строки. Тип можно объявить после первого использования; все типы разрешаются после чтения исходников. Имя типа уникально и не совпадает со встроенным или зарегистрированным типом. Прямая и косвенная рекурсия запрещены, даже если тип пока не используется.

`@param article Article` создает объект (`group`), `@param related Article[]` — массив объектов (`repeater`). Массивы встроенных типов (`String[]`, `Number[]`) и многомерная запись `Article[][]` не поддерживаются. Для списка строк объявите объект с одним строковым полем. Вложенные массивы создаются полем авторского типа, например `@param replies Reply[]` внутри `Comment`.

Путь к полю объекта — `{{article.author.name}}`. Массив читается через `@each`; обращения `related.0.title` и `related[0].title` в разметке недопустимы.

Без `label` одиночный объект не показывает рамку и заголовок группы. Непустой `label` включает их, пустая или состоящая из пробелов строка оставляет поля без оформления группы. У повторяемого списка без `label` используется имя параметра.

Для массива действуют `0 <= min_items <= max_items <= 50`; по умолчанию `0` и `50`. Начальное содержимое без явного default — ровно `min_items` объектов, каждый с defaults дочерних полей. У объекта default собирается из его полей. Авторский DSL не разбирает JSON в `default`: `default='{"name":"Анна"}'` останется строкой и не подойдет объекту. Задавайте defaults дочерним полям или используйте объект/массив `default` в нормализованном JSON. `previewData` позволяет отдельно указать демонстрационное содержимое.

## Блоки, layout и область видимости

### `@block` и `@render`

```html
@block authorCard(person: Author, heading: String) aiInstructions="Представь автора кратко."
<aside><h2>{{heading}}</h2><p>{{person.name}}</p></aside>
@endblock
```

Вызов в `@layout` или другом блоке:

```text
@render authorCard(article.author, title)
```

`@block name(arg: Type, other: OtherType)` объявляет именованный фрагмент разметки. Аргументов может не быть: `@block footer()` вызывается через `@render footer()`. Имена блоков и имена аргументов в одном блоке уникальны. Единственная опция блока после скобок — `aiInstructions`.

Аргументы передаются позиционно. Каждый аргумент вызова — путь к настройке, аргументу текущего блока или элементу цикла. Строковые/числовые литералы, вычисления, именованные аргументы и значения по умолчанию аргументов не поддерживаются. Число аргументов должно совпадать, а тип сравнивается точно: `String` и `Text` различны, как и два разных авторских типа с одинаковыми полями. Блок можно объявить после вызова; рекурсивные цепочки вызовов запрещены.

В блоке доступны его аргументы и корневые настройки. Локальный аргумент с тем же именем перекрывает корневое поле. Переменные вызывающего блока и псевдонимы его цикла передавайте явно аргументами; они не становятся аргументами вложенного блока автоматически. Компилятор сохраняет ссылки на переданные объекты и элементы даже во вложенных циклах.

`aiInstructions` у поля, объекта, массива и блока сохраняются отдельно от `help`, defaults и разметки. Они не запускают генерацию и не подставляют `{{…}}` внутри текста инструкций. Инструкции группы или блока не копируются в дочерние поля. Данные блока сохраняются в `blocks.<name>.aiInstructions`; само тело блока при компиляции разворачивается в HTML.

### `@layout`

```html
@layout
<main><h1>{{title}}</h1></main>
@endlayout
```

Каждая DSL-страница имеет ровно один layout без аргументов. Внутри него разрешены текст/HTML, подстановки, `@render`, `@each`, `@if` и поддерживаемые CSS-директивы. Объявления настроек, типов и блоков размещайте вне layout. Вне `@layout`/`@block` обычная разметка не допускается.

В многостраничном шаблоне настройки, типы и блоки общие, а layout принадлежит конкретной странице. Секции должны быть закрыты до перехода к следующему файлу страницы. Импортер может оборачивать обычные website-страницы в неявный layout; правила имен файлов и такого импорта описаны в [руководстве](templates.md).

### `@include`

```text
@include "types/article.tpl"
@include "blocks/article.tpl"
```

При импорте ZIP путь разрешается от корня пакета, а не от каталога текущего исходника. Подключаемый файл должен существовать внутри пакета; обход каталогов и обратные косые черты запрещены. Отдельный загружаемый текстовый файл не имеет файлового окружения для `@include`.

Include выполняет текстовое раскрытие до разбора деклараций и не создает отдельную область имен. Типичное применение — общие типы и блоки верхнего уровня. Можно также включить фрагмент HTML внутрь layout/блока или набор `@param` внутрь типа: содержимое проверяется по правилам места вставки. Поэтому фрагмент с `@type` нельзя включать внутрь layout.

Повторное подключение повторно добавляет объявления и может вызвать ошибку дубликата; механизма `include_once` нет. Подключения могут быть вложены, циклы запрещены. Сообщения об ошибках DSL сохраняют путь и номер строки исходного фрагмента.

## Подстановка, циклы и условия

### `{{path}}`

```html
<h1>{{ title }}</h1>
<img src="{{article.author.photo}}" alt="{{article.author.name}}">
```

Пробелы вокруг пути допустимы. Подставляются только отдельные скалярные поля: попытка вывести `{{article}}` или `{{reviews}}` отклоняется. Имена проверяются при компиляции, поэтому неизвестное поле — ошибка шаблона, а не пустая строка.

Обычный вывод экранирует HTML, включая `&`, `<`, `>`, одинарную и двойную кавычки. Это подходит для текста HTML и значений атрибутов в кавычках. Это не JavaScript-, CSS- или URL-кодирование: для динамических стилей выбирайте типы `Color`/`Number` с ограничениями, а для адресов — `Url`/`Image`. Произвольный текст не вставляйте в исходник JavaScript; передавайте его через атрибуты `data-*`. Обычная HTML-разметка самого шаблона остается авторским кодом.

Значения не проходят второй раз через DSL: строка `{{title}}` внутри значения останется текстом. Макросы с одинарными скобками обрабатываются отдельным [runtime](template-runtime.md).

### `@each`

```html
@each item in related:
<h2>{{item.title}}</h2>
<p>{{item.author.name}}</p>
@endeach
```

Двоеточие после пути необязательно. Коллекция должна быть массивом авторского типа. Внутри тела `item` имеет тип одного элемента и доступен во вложенных блоках/циклах согласно правилам области видимости. Пустой массив ничего не выводит. Псевдоним существует только в теле цикла; индекс, счетчик, `first`, `last`, `break`, `continue` и отдельная ветка для пустого списка не предоставляются.

### `@if`

```html
@if article.author.photo
<img src="{{article.author.photo}}" alt="{{article.author.name}}">
@endif
```

Условие — один путь без двоеточия и без выражения сравнения. `@if` принимает скалярное поле или объект, но не массив: для массива нужен `@each`. Проверка использует логическое значение PHP: `false`, `0`, `0.0`, `""` и строка `"0"` ложны; строка `"false"` истинна. Объект с полями считается истинным даже тогда, когда значения всех его полей пусты или ложны; объект без полей ложен.

У DSL v1 нет `@else`, `@elseif`, `@unless`, отрицания, `&&`, `||`, сравнений, арифметики, функций, фильтров, строковых литералов в выражениях и тройных фигурных скобок. При необходимости задайте отдельное поле `Boolean`. В нормализованном JSON есть инвертированные секции, но их запись `{{^path}}` нельзя вставлять в авторский DSL.

## Данные preview

`previewData` — отдельный набор значений для снимка шаблона, который не меняет defaults формы:

```html
@template "Демонстрация" version=1
@previewData
{
  "title": "Пример заголовка",
  "article": {"body": "Первая строка\nВторая строка"},
  "comments": [{"body": "Короткий отзыв"}]
}
@endpreviewData
@type Article
@param body Text
@endtype
@param title String = "Новая статья" required
@param article Article
@param comments Article[]
@layout
<h1>{{title}}</h1><p style="white-space:pre-line">{{article.body}}</p>
@each comment in comments
<blockquote>{{comment.body}}</blockquote>
@endeach
@endlayout
```

Блок `@previewData … @endpreviewData` размещается на верхнем уровне вне секции и не принимает аргументов. Его содержимое — JSON-объект, не массив, строка или `null`. Обычные JSON-экранирования внутри многострочного блока сохраняются до JSON-разбора. Пропущенные ключи дополняются defaults, неизвестные ключи и неверные значения отклоняются; проверяются также обязательность полей и размеры массивов.

Для коротких значений есть запись `@template "Demo" previewData='{"title":"Пример"}'`. Она сначала проходит разбор строк DSL, поэтому для JSON с обратными косыми чертами удобнее многострочный блок. Разрешено только одно объявление previewData: либо опция заголовка, либо блок. `{}` явно включает preview на defaults; отсутствие previewData и previewUrl не создает preview.

Опция `previewUrl="https://example.com/demo"` задает публичную HTTP(S) страницу для снимка. Нельзя использовать учетные данные, приватные адреса и нестандартные порты: допустимы 80 и 443. При наличии обоих вариантов URL имеет приоритет для снимка, а previewData все равно проходит проверку. Настройка выполнения снимков описана в [руководстве](templates.md).

## Нормализованный JSON v1

`TemplateSourceParser` создает определение, `TemplateMarkupCompiler` раскрывает типизированные блоки, а `TemplateEngine::validateDefinition()` проверяет и дополняет схему. JSON можно передать непосредственно в `TemplateEngine::parse()`. Это не означает, что произвольный `.json` можно загрузить через форму импорта: форматы пакетов описаны отдельно в [руководстве](templates.md).

### Структура определения

| Свойство | Правила |
| --- | --- |
| `version` | Обязательное целое `1`. |
| `name` | Обязательная непустая строка, до 200 байтов. |
| `description` | До 2000 байтов; по умолчанию `""`. |
| `sections` | Обязательный массив, до 50 секций; может быть пустым. |
| `sections[].id` | Уникальный идентификатор. |
| `sections[].label` | Обязательная непустая строка до 200 байтов. |
| `sections[].fields` | Массив определений полей. |
| `html` | Обязательная непустая разметка главной страницы, до 2 МиБ. |
| `entrypoint` | `index.html` по умолчанию или `index.php`. |
| `pages` | Объект дополнительных выходных путей и их разметки, до 100 записей. |
| `partials` | Объект именованных строковых фрагментов, до 50 записей; фрагмент может быть пустым. |
| `blocks` | Метаданные до 200 блоков в форме `{"name":{"aiInstructions":"…"}}`; не определения исполняемой разметки. |
| `previewData` | Объект значений формы, проходящий обычную нормализацию. |
| `previewUrl` | Публичный HTTP(S) URL preview. |
| `source` | Необязательная строка до 255 байтов с именем авторского исходника; служебные метаданные. |

Пути `pages` безопасны, относительны и оканчиваются на `.html` или `.php`; они уникальны без учета регистра, включая `entrypoint`. Каталоги `_media/` и `_uploads/` зарезервированы. Каждая страница ограничена 2 МиБ, сумма `html`, `pages` и `partials` — 4 МиБ.

Поле содержит `name`, `type`, `label` и опции. `type` — именно внутреннее имя из таблицы типов, не `String`/`Article`. `group` и `repeater` содержат рекурсивный массив `fields`; отдельной таблицы `types` в JSON нет. `label` можно опустить только у `group`; у прочих контролов JSON должен содержать непустую подпись. `required` — JSON boolean, числовые ограничения — JSON numbers, `min_items`/`max_items` — целые JSON numbers. `default` объекта — объект, `default` списка — массив объектов. `options` — отображение ключей в подписи. Сохраненное `author_type` является метаданными исходного DSL, а не новым контролом.

После проверки появляются значения `help: ""`, `required: false`, стандартные границы массива и другие нормализованные значения. Неизвестные ключи верхнего уровня не становятся расширениями языка: движок пересобирает определение из поддерживаемых свойств.

### Разметка JSON

| Выражение | Действие |
| --- | --- |
| `{{title}}`, `{{article.title}}` | Экранированный вывод скалярного поля. |
| `{{& article}}` | Очищенное форматированное содержимое `wysiwyg`/`markdown`. |
| `{{#enabled}}…{{/enabled}}` | Тело один раз при истинном скалярном значении. |
| `{{#author}}…{{/author}}` | Тело в контексте непустого объекта `group`. |
| `{{#reviews}}…{{/reviews}}` | Тело для каждого объекта `repeater`. |
| `{{^reviews}}…{{/reviews}}` | Инвертированная секция: тело при ложном значении, в том числе пустом списке. Контекст не меняется. |
| `{{>reviewCard}}` | Вставка `partials.reviewCard` с текущим контекстом. |
| `{{../title}}`, `{{../../title}}` | Явный родительский контекст. |
| `{{@root.title}}` | Корневые настройки. |

Без явного префикса поле ищется от текущего контекста к внешним. Вход в положительную секцию объекта/списка добавляет контекст; скалярная и инвертированная секции его не добавляют. Partial не добавляет контекст и не принимает аргументы. Переход выше корня, неизвестные поля и неизвестные partials отклоняются. Рекурсивные partials запрещены.

Не смешивайте синтаксисы: `@render` и `@each` принадлежат исходному DSL, `{{#…}}`, `{{^…}}`, `{{>…}}`, `../` и `@root.` — нормализованной разметке. В DSL привязки к родителям формирует компилятор из имен аргументов и псевдонимов циклов. Движок не является полным Mustache: нет комментариев, смены разделителей, `{{.}}`, лямбд и произвольного raw HTML; `{{&…}}` ограничен rich text.

### Полный JSON-пример

Этот объект можно передать в `TemplateEngine::parse()`, затем вызвать `render($definition, [])`:

```json
{
  "version": 1,
  "name": "Отзывы — JSON",
  "sections": [
    {
      "id": "content",
      "label": "Содержание",
      "fields": [
        {"name": "title", "type": "text", "label": "Заголовок", "default": "Отзывы"},
        {
          "name": "reviews",
          "type": "repeater",
          "label": "Отзывы",
          "min_items": 0,
          "max_items": 10,
          "fields": [
            {"name": "author", "type": "text", "label": "Автор", "default": "Гость"},
            {"name": "body", "type": "markdown", "label": "Текст", "default": ""}
          ],
          "default": [{"author": "Анна", "body": "**Спасибо!**"}]
        }
      ]
    }
  ],
  "html": "<main><h1>{{title}}</h1>{{#reviews}}{{>reviewCard}}{{/reviews}}{{^reviews}}<p>Пока нет отзывов.</p>{{/reviews}}</main>",
  "partials": {
    "reviewCard": "<article><h2>{{author}}</h2><div>{{&body}}</div><small>{{@root.title}}</small></article>"
  }
}
```

С пустым объектом значений выводится отзыв Анны из default. При передаче `['reviews' => []]` вместо него выводится «Пока нет отзывов.». В обоих случаях пропущенный `title` берется из default.

## Ограничения и диагностика

| Объект проверки | Ограничение |
| --- | --- |
| Исходники DSL после учета include | По умолчанию 2 МиБ (`fast-landings.templates.max_definition_bytes`), 20 000 строк на весь набор страниц и включений. Повторные include учитываются повторно. |
| Цепочка include | До 10 вложенных переходов; циклы запрещены. |
| Схема формы | До 50 секций, 200 полей с учетом раскрытых авторских типов, до 6 уровней списков полей включая корневой. |
| Массив объектов | До 50 элементов на каждом поле. |
| Значения и defaults | Общий бюджет 10 000 учитываемых элементов/значений, включая вложенность. |
| Директивы `@each`/`@if` | До 20 уровней вложенности. |
| Вызовы блоков | До 20 блоков в цепочке; бюджет раскрытия 50 000 операций и предел размера раскрытой разметки. |
| Исходный JSON для `parse()` | До 8 МиБ; глубина JSON-декодирования до 64. |
| Нормализованные секции `{{#…}}`/`{{^…}}` | До 24 уровней. |
| Partials | До 50 определений, цепочка до 16 без рекурсии. |
| Компиляция нормализованной разметки | Бюджет 10 000 узлов разбора и 50 000 операций обхода/раскрытия; это не только число видимых подстановок. |
| Рендер страницы | До 200 000 операций, глубина до 64, по умолчанию 8 МиБ результата (`fast-landings.templates.max_render_bytes`). |

Ошибка исходного DSL обычно содержит `файл:строка: сообщение`, например `blocks/card.tpl:2: Unknown field article.missing.`. Проверка нормализованной схемы сообщает путь к свойству, а проверка значений — путь вида `values.reviews.0.author`. Ошибки, обнаруженные уже после нормализации, не обязательно сохраняют номер строки исходника.

Практические причины ошибок: незакрытый блок, директива на строке вместе с HTML, повторяющиеся корневые имена, несовпадение точных типов аргумента блока, массив встроенного типа, условие по массиву, JSON-строка вместо объекта, неизвестный параметр, неподдерживаемый `{{#…}}` в авторском DSL или пустое обязательное значение в preview.

## Где проверять поведение в коде

- Общий parser [TemplateSourceParser](https://github.com/TrafficOps-io/tops-templates/blob/main/template-dsl/src/TemplateSourceParser.php) — строки, декларации, include, типы и страницы; интеграция Fast Landings покрыта [его app-тестами](../../tests/Unit/TemplateSourceParserTest.php).
- Общий compiler [TemplateMarkupCompiler](https://github.com/TrafficOps-io/tops-templates/blob/main/template-dsl/src/TemplateMarkupCompiler.php) — пути, строгие типы аргументов, область видимости и раскрытие блоков.
- Общий registry [TemplateFieldTypes](https://github.com/TrafficOps-io/tops-templates/blob/main/template-dsl/src/TemplateFieldTypes.php) — соответствие авторских типов контролам и преобразование defaults.
- Общий [TemplateEngine](https://github.com/TrafficOps-io/tops-templates/blob/main/template-dsl/src/TemplateEngine.php) — JSON-схема, defaults, значения, partials и рендер; Fast-совместимость покрыта [app-тестами](../../tests/Unit/TemplateEngineTest.php).
- Общие [TemplateRichText](https://github.com/TrafficOps-io/tops-templates/blob/main/template-dsl/src/TemplateRichText.php) и [TemplateImageOptions](https://github.com/TrafficOps-io/tops-templates/blob/main/template-dsl/src/TemplateImageOptions.php) — форматированный текст и ограничения изображений.
- App-owned [FastLandingsTemplateDialect](../../app/Services/Templates/FastLandingsTemplateDialect.php) — доверенный PHP/request-runtime профиль поверх общего core.

Разработчик приложения может зарегистрировать дополнительный авторский тип через singleton `TemplateFieldTypes::register()`. Фабрика из кода приложения отображает его в существующий контрол и задает presets; загруженный шаблон не может передавать такую фабрику. Добавление нового внутреннего контрола требует поддержки в валидаторе и форме. Для группировки существующих полей достаточно авторского `@type`.
