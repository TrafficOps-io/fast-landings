# Шаблоны Fast Landings

Шаблон объединяет HTML, типизированные настройки и повторно используемые блоки. Fast Landings строит по объявлениям форму, а при сохранении лендинга подставляет её значения в страницы и создаёт выпуск сайта. Один шаблон можно использовать для нескольких лендингов с разными текстами, изображениями и списками.

Документация соответствует DSL v1 в текущей реализации приложения:

- **Это руководство** — создание шаблона, ZIP-пакеты, изображения, превью, AI и обновление лендингов.
- [Справочник DSL](template-dsl.md) — все объявления, типы, опции, области видимости, ограничения и внутренний JSON-формат.
- [HTTP-макросы, формы и PHP](template-runtime.md) — данные посетителя, `@validation`, перенаправления и выполнение PHP.
- [English authoring guide](../templates.md).

## Быстрый старт

Сохраните этот полный пример в UTF-8 как `template.tpl`:

```html
@template "Карточка предложения" version=1 description="Заголовок, описание и преимущества"

@section content "Содержимое"
@param title String = "Попробуйте новый сервис" label="Заголовок" required
@param description Markdown = "Всё необходимое **в одном месте**." label="Описание"
@param target Url = "https://example.com/offer" label="Адрес кнопки" required
@param button String = "Подробнее" label="Текст кнопки" required
@endsection

@type Benefit
@param text String = "Удобно каждый день" label="Преимущество" required
@endtype
@param benefits Benefit[] label="Преимущества" min_items=1 max_items=6

@block benefitItem(item: Benefit)
<li>{{item.text}}</li>
@endblock

@layout
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{{title}}</title>
</head>
<body>
  <main>
    <h1>{{title}}</h1>
    <div>{{& description}}</div>
    <ul>
      @each benefit in benefits:
        @render benefitItem(benefit)
      @endeach
    </ul>
    <a href="{{target}}">{{button}}</a>
  </main>
</body>
</html>
@endlayout
```

1. Администратор открывает **Templates** (`/admin/templates`) и импортирует файл.
2. Активный пользователь панели выбирает **Create landing**, задаёт имя и slug лендинга, заполняет настройки. В списке преимуществ сразу есть одна строка; можно добавить ещё пять.
3. **Create landing** создаёт активный выпуск с `index.html`. Чтобы сайт стал доступен посетителям, назначьте ему домен по [руководству по доменам](../domains.md).

`{{title}}` экранирует текст, `{{& description}}` преобразует Markdown в очищенный HTML, а `@render` вызывает блок для каждого элемента списка. Название секции `content` организует форму: путь остаётся `title`, а не `content.title`. Каждая директива должна находиться на отдельной строке.

## Что происходит с шаблоном

```text
TPL / ZIP → разбор и проверка → шаблон в библиотеке → форма настроек
                                                          ↓
                                   значения + изображения + файлы
                                                          ↓
                                      компиляция → новый выпуск
                                                          ↓
                                      назначенный домен → посетитель
```

Есть два разных момента подстановки данных:

| Запись | Источник | Когда вычисляется |
| --- | --- | --- |
| `{{title}}` | Сохранённое поле формы | При создании выпуска |
| `{{& article}}` | Поле `Wysiwyg` или `Markdown` | При создании выпуска, с очисткой HTML |
| `{query.subid}`, `{body.name}` | HTTP-запрос посетителя | При каждом запросе страницы |
| `<?php … ?>`, `<?= … ?>` | Код автора сайта | В отдельном PHP runtime при запросе |

Макрос запроса можно записать и в значение текстового поля, например `Спасибо, {body.name}!`. При публикации поле попадёт в страницу, а имя посетителя будет подставлено позднее. Такая страница требует PHP runtime, даже если исходник назывался `.html`. Правила и примеры — в [руководстве по HTTP-макросам](template-runtime.md).

## Один файл или ZIP-пакет

Импорт принимает один файл `.html`, `.php`, `.txt`, `.tpl` или один `.zip`. Исходники — UTF-8 без нулевых байтов. Отдельный `.json` через форму импорта не загружается: [нормализованная JSON-схема](template-dsl.md) предназначена для кода приложения.

В ZIP должна быть ровно одна входная точка из списка:

```text
template.html   template.txt   template.tpl
index.html     index.php      index.tpl.html   index.tpl.php
```

Входной файл находится в корне или в одной общей папке-обёртке со всем содержимым. Не кладите рядом, например, `index.html` и `index.tpl.html`: оба считаются кандидатами на входную точку.

```text
article.zip
├── template.tpl
├── blocks/
│   └── comment.tpl
└── assets/
    ├── style.css
    ├── app.js
    └── avatar.svg
```

Подключите фрагмент через `@include "blocks/comment.tpl"`. Пути включений считаются от корня пакета, в том числе во вложенных фрагментах. Общие объявления удобнее хранить в одном фрагменте и включать один раз: повторный include не обладает семантикой `include_once`.

CSS, JS и картинки подключаются обычными HTML-путями, например `<link rel="stylesheet" href="assets/style.css">`. Это файлы сайта; DSL не подставляет параметры внутри отдельного `.css` или `.js`. Входной исходник, подключённые фрагменты и исходники скомпилированных страниц не копируются в выпуск как публичные файлы. Остальные файлы пакета копируются с сохранением путей.

Папки `_uploads/` и `_media/` зарезервированы для изображений пользователя. Пакет не может подменить этими путями загруженные изображения или занять имя генерируемой страницы. Выход за корень, символьные ссылки, коллизии путей и превышение лимитов распаковки отклоняются.

### Несколько страниц

```text
Исходный ZIP                   Выпуск без HTTP-макросов
index.tpl.html                index.html
success.tpl.php               success.php
legal/privacy.tpl.html        legal/privacy.html
assets/site.css               assets/site.css
lib/helpers.php               lib/helpers.php
```

`template.html`, `template.txt` и `template.tpl` дают `index.html`; суффиксы `.tpl.html` и `.tpl.php` превращаются в `.html` и `.php`. Обычные дополнительные HTML/PHP-файлы копируются как файлы сайта; чтобы подставить в дополнительную страницу настройки DSL, назовите её `*.tpl.html` или `*.tpl.php`.

Все страницы используют общие настройки, типы и блоки. Объявляйте каждое имя один раз на пакет; единственный `@template` удобно размещать во входном файле. Секции страниц тоже должны иметь разные идентификаторы. Если включённый фрагмент заканчивается на `.tpl.html` или `.tpl.php`, импортёр исключит его из самостоятельных страниц.

В каждой странице с объявлениями настроек, типов или блоков задавайте явную пару `@layout` / `@endlayout`. Для обычной разметки с интерполяциями импортёр может добавить layout сам. Старые входные точки `template.*` всегда требуют явный layout. `@validation` обрабатывается отдельно и может находиться в странице с неявным layout.

Ссылки, `form action`, PHP include и `fallback` пишите с учётом **конечных имён файлов**. Страница с HTTP-макросом или валидацией меняет расширение `.html` на `.php`; ссылки в исходнике автоматически не переписываются. Маршрутизация приложения и актуальная конфигурация Caddy поддерживают внутренний переход с отсутствующего `.html` на одноимённый `.php`, сохраняя query и тело запроса. Для формы удобнее сразу использовать `success.tpl.php` и ссылаться на `success.php`. На вложенных страницах учитывайте обычное разрешение URL браузером: `assets/site.css` в `legal/privacy.html` означает `/legal/assets/site.css`; для общих файлов можно писать `/assets/site.css`.

## Тексты и изображения

Обычные `String` и `Text` содержат текст. HTML внутри них будет показан экранированным. Для переноса строк `Text` подходит `white-space: pre-line` на контейнере. `Wysiwyg` хранит HTML, а `Markdown` — исходный Markdown; выводите их через `{{& field}}` в `div`, `article`, `section` или другом контейнере тела страницы.

```html
@param article Wysiwyg = "<p>Текст <strong>статьи</strong>.</p>" label="Статья"
@param details Markdown = "## Подробности\n\nПервый абзац." label="Подробности"
@param cover Image label="Обложка" aspect_ratio="16:9"
@param avatar Image label="Аватар" sizes="256x256|512x512"
```

Это фрагмент объявлений: добавьте его перед layout своего шаблона. Пример размещения в layout:

```html
@if cover
<img src="{{cover}}" alt="Обложка">
@endif
<article>{{& article}}</article>
<section>{{& details}}</section>
```

Редакторы работают и во вложенных объектах и списках. Markdown Preview использует тот же серверный рендерер, что и публикация. Сохраняются заголовки, абзацы, списки, цитаты, код, ссылки и изображения. HTML из Markdown удаляется, а форматированный результат обоих редакторов проходит очистку от скриптов, обработчиков событий, стилей, iframe, SVG-разметки и небезопасных URL. Типографику задаёт сам шаблон, например `article img { max-width: 100%; height: auto; }`.

### Поле Image и обрезка

`Image` принимает HTTP(S)-URL, путь к файлу пакета или загрузку. Файл загрузки имеет приоритет перед текстовым значением. Относительная картинка должна присутствовать в пакете или среди сохранённых загрузок: при публикации проверяется её наличие. Сервер не скачивает внешние URL и не изменяет размеры таких изображений.

- `aspect_ratio="16:9"` фиксирует пропорции обрезки; в текстовом DSL используйте запись `ширина:высота`.
- `sizes="1200x630|1080x1080"` задаёт от 1 до 10 различных вариантов точного размера. Каждое измерение — от 1 до 4096 пикселей.
- Эти опции взаимоисключающие. Без них доступны исходные пропорции и изменение размера.

Редактор позволяет масштабировать, сдвигать изображение и сохранять прозрачность. Применение обрезки создаёт статический PNG; **Use original** оставляет файл без преобразования, сохраняя анимацию. Ограничения шаблона всё равно проверяются сервером для новой загрузки. Внешнее изображение можно обрезать в браузере, если его сервер разрешает CORS.

Новые загрузки принимают JPEG, PNG, GIF, WebP и AVIF до 10 МБ (`fast-landings.templates.max_image_kb`). Путь изображения `Image` попадает в `_uploads/`, а изображение из тулбара текстового редактора — в `_media/`. Встроенный SVG можно положить в assets; загрузка SVG через эти поля не поддерживается.

### Хранение изображений редакторов

Оригиналы из редакторов хранятся на Laravel Filesystem disk, заданном `FAST_LANDINGS_MEDIA_DISK`; по умолчанию берётся `FILESYSTEM_DISK` (`local`). Можно выбрать `s3` или другой настроенный disk. Учётные данные S3 задаются в [config/filesystems.php](../../config/filesystems.php). Превью доступны через авторизованный маршрут панели, поэтому публичный bucket или `storage:link` не требуются.

При публикации используемые изображения копируются в выпуск под `_media/`; ссылки остаются относительными. Диск и путь оригинала записаны в `template_media`, поэтому смена disk влияет на новые загрузки. При редактировании сохраняющиеся изображения переносятся из предыдущего выпуска. Откат использует файлы выбранного выпуска. Настройка media disk не переносит само хранилище выпусков в S3.

## Превью в библиотеке

Добавьте перед layout один блок с демонстрационными значениями. Например, для шаблона из быстрого старта:

```text
@previewData
{
  "title": "Сервис для вашей команды",
  "benefits": [
    {"text": "Быстрый запуск"},
    {"text": "Понятные настройки"}
  ]
}
@endpreviewData
```

Пропущенные поля заполняются значениями по умолчанию. Объекты и списки должны соответствовать схеме; неизвестные поля и невалидные значения отклоняются при импорте. Пустой объект `{}` включает превью с defaults. Демоданные не меняют исходные настройки новых лендингов.

Для короткого объекта есть запись `@template "Пример" previewData='{"title":"Демо"}'`. Указывайте previewData только одним способом. Для сложного JSON используйте блок: внутри строк опций DSL обратные слеши JSON требуют дополнительного экранирования.

Вместо локальной сборки можно указать `previewUrl="https://example.com/demo"` в строке `@template`. Нужна публичная HTTP(S)-страница без credentials, с портом 80 или 443. При наличии обоих вариантов URL имеет приоритет, но `previewData` всё равно проверяется. Локальные и приватные сетевые адреса не подходят.

Скриншоты создаёт Chromium через очередь. Воркер локального превью не выполняет PHP: для входной PHP-страницы используйте публичный `previewUrl`. HTML-входная страница с дополнительным PHP-обработчиком может иметь локальное превью; сам обработчик в него не входит. Локальная картинка не проверяет работу формы или значения реального HTTP-запроса.

На карточке администратор может обновить превью или повторить неудачную генерацию. Настройка очереди, Chromium и команды восстановления описаны в [README](../../README.md#landing-library-screenshots-and-tags).

## Подготовка контента с AI

В **Create landing → Generate content with AI** выберите подключение и опишите тему, язык, аудиторию и желаемый результат. Подключения настраивает администратор в **AI integrations**; ключи хранятся на сервере.

1. При необходимости задайте точное число элементов списков. Оно имеет приоритет перед текстовым запросом, соблюдает границы схемы и применяется к каждому соответствующему вложенному списку.
2. **Images for the site** — изображения, которые можно поместить в поля и статью. **Reference images** — визуальные ориентиры, которые не упаковываются в сайт.
3. Если нужны новые изображения, выберите поля в **Generate new images**. Поле внутри списка создаёт по изображению для каждого элемента.
4. Запустите **Generate content**, дождитесь результата и выберите **Apply to editor**. Это заменяет текущие значения формы. Проверьте их и только затем создавайте лендинг.

Автор шаблона может направлять генерацию через `aiInstructions` у поля, группы, списка или блока. Аннотация сама не запускает AI и не является текстом подсказки в форме:

```text
@param title String label="Заголовок" aiInstructions="Коротко сформулируй пользу, без преувеличений."
```

AI получает схему, текущие значения, инструкции и контекст layout; возвращает значения полей. Ответ проверяется по схеме до применения. Генерация выполняется в очереди и не публикует выпуск. Незавершённые загрузки непосредственно в поля нужно убрать или перенести в **Images for the site** перед запуском и применением. Если шаблон изменился, требуется новый результат генерации.

Лимиты: до 8 загружаемых изображений каждого назначения, до 10 МБ на файл, до 20 МБ суммарно и до 25 мегапикселей на изображение; до 8 генерируемых изображений после раскрытия списков. Поддержка провайдеров, переменные моделей и параметры очереди описаны в [английском руководстве](../templates.md#providers-and-models) и [config/ai.php](../../config/ai.php).

## Изменение шаблона и лендинга

| Действие | Что изменится |
| --- | --- |
| **Templates → Edit → Save template** | Название, описание и, при выборе Replacement file, пакет шаблона. Его идентификатор сохраняется. |
| **Templates → Files → Save template** | Публикуется отредактированный исходный пакет. Новая схема проверяется перед заменой. |
| **Edit template data → Save and activate** | Из сохранённых значений и текущего шаблона создаётся новый активный выпуск лендинга. |
| **Change template** | Форма переключается на выбранный шаблон; после сохранения создаётся новый выпуск. |
| **Replace with ZIP archive** | Выпуск заменяется обычным сайтом; активная связь с шаблоном очищается. |
| **Use a template** | Лендинг из обычного ZIP получает выпуск, созданный из шаблона. |
| **Edit files → Save and activate** на лендинге | Создаётся выпуск с управлением через файлы; предыдущий выпуск сохраняет данные шаблона. |
| Активация старого выпуска | Восстанавливаются его файлы и сохранённые настройки шаблона. |
| Удаление шаблона | Уже созданные выпуски продолжают работать; для дальнейшего редактирования полей нужен доступный шаблон. |

Управление библиотекой шаблонов доступно администраторам; создание лендингов — активным пользователям панели. Замена шаблона не пересобирает уже опубликованные сайты. Следующее сохранение полей использует актуальную схему: переименование или изменение типа поля может потребовать исправления старых значений. Имя и описание в форме редактирования библиотеки имеют приоритет над объявлениями из Replacement file.

Обновление лендинга сохраняет его идентификатор, домены и статус публикации. Выпуски сохраняют собственные `template_values`; откат не восстанавливает старую версию исходного пакета библиотеки. Если после открытия редактора другой пользователь активировал выпуск, перезагрузите форму перед сохранением. Ошибка проверки или компиляции оставляет прежний выпуск действующим.

В файловом редакторе изменения находятся в черновике до явного сохранения шаблона или активации выпуска. При переименовании файлов поправьте ссылки на них. Отмена удаляет черновик. Ctrl/Cmd+S сохраняет текущий файл в черновик, а не публикует сайт.

## Ошибки и ограничения

| Симптом | Что проверить |
| --- | --- |
| `The ZIP must contain exactly one …` | Одна входная точка из допустимого списка; нет второй рядом или файлов за пределами обёртки. |
| `Unknown …`, `Unexpected …`, `Missing …` | Регистр имени, закрывающие директивы, отдельные строки, объявление поля/типа/блока и область видимости. |
| Нельзя вывести объект в `{{…}}` | Укажите конечное поле (`{{header.title}}`) или разверните список через `@each`. |
| HTML показан текстом | Для форматированного текста используйте `Wysiwyg`/`Markdown` и `{{& field}}`. |
| `This image is not included in the template …` | Наличие относительного файла в ZIP, сохранённой загрузки или корректного HTTP(S)-URL. |
| `Crop the image …` | Загружаемый файл должен соответствовать `sizes` или `aspect_ratio`. |
| Страница с макросами недоступна | PHP runtime, актуальную конфигурацию маршрутизации и конечное имя страницы; подробнее в [руководстве runtime](template-runtime.md). |
| Нет превью | Наличие previewData/previewUrl, воркера очереди и Chromium; для PHP — публичного demo URL. |
| Старый лендинг больше не проходит проверку полей | Библиотечный шаблон изменился; приведите данные к новой схеме. |

Основные лимиты по умолчанию из [config/fast-landings.php](../../config/fast-landings.php):

| Ограничение | Значение | Настройка |
| --- | --- | --- |
| Загружаемый архив | 100 МБ | `FAST_LANDINGS_MAX_UPLOAD_MB` |
| Распакованное содержимое | 300 МБ | `FAST_LANDINGS_MAX_EXTRACTED_MB` |
| Число файлов | 5000 | `FAST_LANDINGS_MAX_FILES` |
| Коэффициент распаковки | 200 | `FAST_LANDINGS_MAX_EXPANSION_RATIO` |
| Размер одного исходника и общий бюджет исходников parser | 2 МБ | `fast-landings.templates.max_definition_bytes` |
| Результат рендера одной страницы | 8 МБ | `fast-landings.templates.max_render_bytes` |
| Загрузка изображения | 10 МБ | `fast-landings.templates.max_image_kb` |
| Значение Wysiwyg/Markdown | 100 000 байт UTF-8 | `TemplateRichText::MAX_BYTES` |

Дополнительные лимиты числа полей, вложенности, циклов и списков перечислены в [справочнике DSL](template-dsl.md). Текстовый DSL не выполняет Blade, произвольные выражения и функции PHP при импорте. HTML/JS/PHP самого шаблона остаются кодом автора сайта; HTML-экранирование поля не превращает его в безопасный JavaScript или CSS. Для CSS используйте соответствующие `Color`/числовые поля, а данные для JS передавайте через атрибуты `data-*` с последующим чтением из DOM.
